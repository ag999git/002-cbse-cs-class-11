# Chapter 5: glossary

Every word explained in the chapter, in alphabetical order, with the section of the book where it is explained.

- **Algorithm**: a finite list of exact steps that turns the input into the output (5.1).
- **Analyse**: study a problem for its inputs, outputs and rules (5.2).
- **Boundary value**: a value at or just past a limit (5.2).
- **Bug**: a mistake in a program (5.2).
- **Code**: an algorithm in a programming language (5.2).
- **Computational thinking**: decomposition, pattern recognition, abstraction, algorithms (5.9).
- **Condition**: a Yes/No question (5.4).
- **Connector**: a circle joining two parts of a flowchart (5.4).
- **Debug**: find and remove a fault (5.2).
- **Decision**: a choice by a condition; the diamond (5.4).
- **Decomposition**: breaking a problem into parts (5.9).
- **Dry run**: following an algorithm by hand (5.7).
- **Flowchart**: an algorithm drawn with standard symbols (5.4).
- **GIGO**: garbage in, garbage out (5.1).
- **Maintenance**: changes after delivery (5.2).
- **Program**: an algorithm a computer can run (5.1).
- **Pseudocode**: structured English for an algorithm (5.6).
- **Repetition**: doing steps again; a loop (5.4).
- **Sequence**: steps one after another (5.4).
- **Space complexity**: memory needed (5.8).
- **Structure diagram**: a tree of parts (5.9).
- **Syntax**: the grammar of a language (5.2).
- **Test**: run with chosen inputs (5.2).
- **Time complexity**: steps needed (5.8).
- **Trace table**: variable values during a dry run (5.7).
